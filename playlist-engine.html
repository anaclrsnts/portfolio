Playlist Engine

Music Recommendation / Audio Processing / Full-Stack

TYPE: Personal Project

CODE: GitHub

LIVE: Render

Playlist Engine started from a question that connects two parts of my life: my interest in music and my studies in Electronic and Computer Engineering. While studying signal processing — especially audio signals — I became interested in what it would mean to describe a song's "vibe" using measurable information instead of relying only on genre or artist similarity.

The project grew from a simple Spotify-based playlist generator into an experiment in music recommendation. A user chooses one reference song and can decide whether similarity should be based on collective listening patterns, sonic characteristics, or a combination of both. The application then ranks candidate tracks, applies artist diversity, lets the user listen to suggestions, refine the result, and save the final playlist to Spotify.

Technical Overview

The recommendation system has three comparison modes: Listening, Sound, and Hybrid. Listening mode uses track-to-track listening similarity to model the idea of "people who listen to this song also listen to...". Sound mode focuses on musical characteristics such as tempo, energy, valence, danceability, acousticness, and instrumentalness.

In Sound mode, the user can assign different weights to those characteristics. Candidate songs are compared against the reference track and receive a similarity score based on the selected priorities. Tempo is treated carefully so half-time and double-time relationships can still be considered rhythmically close.

Hybrid mode combines the listening-pattern score and the sound-profile score into one weighted ranking. A second diversity step reduces excessive repetition of the same artist, which helps the result feel more like music discovery than a list of tracks from one catalog.

Flask handles the recommendation logic, external API communication, Spotify OAuth, token refresh, and playlist creation. JavaScript manages the interactive comparison controls, loading states, recommendation results, embedded listening player, and save flow.

Main Features

• Search for a reference song using the Spotify catalog.

• Choose between Listening, Sound, and Hybrid recommendation modes.

• Adjust how much tempo, energy, mood, danceability, acousticness, and instrumentalness matter to the sound comparison.

• Balance listening-pattern similarity against sonic similarity in Hybrid mode.

• Control artist diversity to move between more familiar and more exploratory recommendations.

• Display listening, sound, and overall match scores when available.

• Listen to suggested tracks through an embedded Spotify player.

• Remove unwanted tracks and regenerate the playlist with different comparison settings.

• Save the final result to Spotify with automatic session-token refresh and playlist verification.

Application Flow

The user first chooses what "similar" should mean. They can prioritize listening behavior, sonic characteristics, or combine the two. In the sound-oriented modes, the comparison weights can be adjusted before searching for a reference track.

After the user selects a song, the comparison controls disappear and the interface enters a loading state while candidate tracks are collected, analyzed, ranked, and diversified.

The resulting playlist shows the reference track and ranked recommendations. Each suggestion can be previewed through Spotify, removed from the result, or inspected through its match scores.

Choosing "generate again" returns to the comparison controls so the same seed can be explored with different assumptions. When the result is ready, the user can connect Spotify and save the playlist directly to their account.

Challenges

• Turning the subjective idea of a musical "vibe" into a set of measurable and adjustable comparison criteria.

• Separating collaborative listening similarity from sonic similarity instead of treating them as the same recommendation problem.

• Combining several similarity dimensions without allowing one feature — such as tempo or artist identity — to dominate every result.

• Designing artist-diversity rules that encourage discovery without destroying the musical relationship to the seed track.

• Coordinating multiple external services while giving users clear loading, fallback, error, and authentication states.

• Managing Spotify OAuth, expiring access tokens, refresh tokens, and verified playlist creation in a deployed Flask application.

What I Learned

• This project helped me connect concepts from signal processing with a full-stack application instead of studying them only as isolated mathematical tools.

• I became more interested in how audio can be represented through descriptors such as tempo, energy, spectral and timbral information, and how those measurements can support similarity systems.

• I learned that recommendation is not a single definition of similarity: behavioral similarity and acoustic similarity can lead to very different but equally meaningful results.

• I practiced building weighted ranking logic and designing an interface that exposes those assumptions to the user instead of hiding them inside the algorithm.

• I also strengthened my understanding of Flask APIs, asynchronous JavaScript flows, OAuth, deployment, external-service failures, and stateful user interactions.

Why This Project Matters to Me

I am especially interested in this project because it sits directly between software development and my engineering studies. Music has always been one of my strongest personal interests, and studying signal processing made me want to understand music not only as something I listen to, but also as a signal that can be measured, represented, and compared.

Playlist Engine gives me a practical space to explore that connection. My next goal is to keep pushing the sound-comparison side further, especially with audio-processing techniques such as spectral descriptors, chroma, MFCCs, and similarity between feature vectors. For me, the project is less about recreating a commercial recommender and more about learning how engineering concepts can shape a playful, useful music experience.
